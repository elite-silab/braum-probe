# Braum Agent 监控平台改造实施计划

**目标：** 将当前由 Workers 中心 Cron 模拟多节点探测的实现，改造成真实 VPS Agent 上报资源指标并从节点本地执行探测的端到端系统。

**架构：** Cloudflare Workers/D1/KV/Pages 继续作为控制面；新增 Go Agent 作为 VPS 数据面。Agent 通过一次性注册令牌换取节点专属密钥，主动上报并获取配置。远程终端独立于 P0 监控协议。

**技术栈：** TypeScript、Hono、Cloudflare Workers、D1、KV、Astro、React、Go、systemd、Vitest。

## 步骤 1：固化数据契约

**输出：** `0005_init_agents.sql`、共享 Agent/指标类型、真实迁移契约测试。

**验证：** SQLite 内存数据库可以应用全部迁移；约束、索引、级联删除和 Upsert SQL 均可执行。

## 步骤 2：实现 Agent 身份生命周期

**输出：** 管理端生成/吊销注册令牌，Agent 注册、密钥摘要验证和密钥轮换 API。

**验证：** 测试覆盖过期令牌、重复使用、错误节点、无效密钥、已暂停/已删除节点和成功注册；响应和审计日志不泄露长期密钥。

## 步骤 3：实现指标与探测协议

**输出：** 心跳接口、资源指标落库、节点信息 Upsert、目标配置下发和探测结果批量上报。

**验证：** 测试覆盖输入范围、批量上限、节点与目标关联校验、KV 最新结果更新和心跳状态迁移。

## 步骤 4：纠正调度语义

**输出：** Cron 只检查 Agent 心跳、聚合与告警，不再代表节点执行目标探测，也不再用探测任务更新节点心跳。

**验证：** 调度测试证明中心 Cron 不调用节点探测引擎，离线判定只依赖 Agent 心跳。

## 步骤 5：实现 Linux Agent

**输出：** Linux amd64/arm64 Go Agent、配置文件、资源采集、HTTP/DNS 探测、指数退避和优雅退出。

**验证：** Go 单元测试、`go test ./...`、`go vet ./...`、两种架构交叉编译。

## 步骤 6：实现安装与发布

**输出：** systemd 安装脚本、卸载/重装流程、校验和文件、可配置 Release 下载地址和跨平台构建工作流。

**验证：** Shell 语法检查；临时目录模拟安装参数与配置权限；构建产物名称与安装脚本匹配。

## 步骤 7：重做节点管理体验

**输出：** 待注册/在线/离线/暂停状态，新增节点后直接进入安装步骤，复制命令、令牌倒计时、重新生成、吊销和 Agent 信息展示。

**验证：** 表单验证、重复点击保护、错误恢复、键盘焦点、移动端布局和浏览器完整注册流程验证。

## 步骤 8：重做公共监控页面

**输出：** 节点卡片显示 CPU/内存/磁盘/网络/负载和数据新鲜度；节点详情展示资源趋势、主机信息、关联目标和探测历史。

**验证：** 加载、空、离线、错误、过期数据和正常状态均有明确视觉反馈；无虚构位置或指标。

## 步骤 9：文档与最终质量门禁

**输出：** README、架构、数据库、部署、后台、前端、安全和 Agent 升级文档全部与实现一致。

**验证：** `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm build`、`go test ./...`、`go vet ./...`、Agent 交叉编译和浏览器视觉检查全部通过。

## P1：远程终端

在 P0 稳定后单独完成威胁建模和 ADR，再实现短时会话票据、Agent 主动 WebSocket、中继/ Durable Object、二次授权、会话吊销和完整审计。不得直接复用永久 Agent 心跳密钥作为浏览器会话凭据。
