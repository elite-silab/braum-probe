# 网络探测目标分配交互设计

## 背景

目标记录和节点分配是两个独立的数据关系。只创建 `targets` 记录不会产生探测结果，只有 `node_targets` 中存在关联，Agent 才会在心跳中收到目标。此前后台创建成功后直接关闭弹窗，用户容易误以为目标已经开始监控。

## 决策

采用“创建后连续引导、关联仍可跳过”的流程：

1. 创建目标只要求地址，保持轻量。
2. 创建成功后进入“下一步：分配探测节点”，列出节点名称与 Agent 安装状态。
3. 用户可选择一个或多个节点保存，也可以暂时跳过，之后从节点编辑页调整。
4. 目标列表展示分配数量；零分配使用“未分配节点”而不是普通空值。

不自动分配到全部节点，避免新增目标后突然增加所有 VPS 的外部请求和流量。

## API

- 目标列表返回 `assigned_node_count`，用于管理列表状态。
- 目标详情返回 `node_ids`，便于后续编辑扩展。
- `PUT /api/admin/v1/targets/:id/assignments` 原子替换目标的节点关联，校验节点存在后写入并通知关联 Agent。

## 文案原则

- “网络探测”解释为“从某台 VPS 访问网站或 DNS”。
- 明确区分资源监控与网络探测。
- 所有空状态都给下一步：创建目标、分配节点、等待首次结果。
