# Braum 前端功能与交互设计

> 版本：v2.7 · 更新：2026-07-27

## 1. 体验目标

公共页面定位为“服务器公开状态页”，需要在十秒内回答三个问题：

1. 哪些服务器正常、离线、暂停或尚未安装探针？
2. 当前 CPU、内存、磁盘、网络和运行时间是否异常，数据是什么时候采集的？
3. 从每台 VPS 到监控目标的延迟和可用率如何？

公共页面优先使用“服务器、探针、网络检查”等普通用户容易理解的词，避免在首屏暴露 Workers、WebSocket 等实现细节。管理后台与安装文档在需要准确说明程序、协议或配置时，仍可使用 Agent 等技术名称。

所有指标必须来自真实 Agent 上报或 Agent 本地探测。地理位置默认由 Agent 请求的 Cloudflare 信息识别，允许管理员手动修正，但不能推导为 Cloudflare 实际执行位置。

## 2. 信息架构

| 页面 | 路由 | 核心内容 |
|---|---|---|
| 状态总览 | `/` | 全局健康、完整节点目录、网络摘要、运行公告 |
| 服务器详情 | `/node/:id` | 当前资源、24h 趋势、主机信息、网络记录、可用率 |
| 网络记录 | `/history` | 按服务器与时间范围筛选 HTTP/DNS 检查结果 |
| 运行公告 | `/incidents` | 故障、维护和恢复时间线 |

桌面端使用顶部导航；移动端使用固定底部导航。节点目录直接位于总览页，点击卡片进入 `/node/:id`，不再提供低使用率的全球地图页面。

## 3. 总览页面

### 3.1 全局健康条

- 首屏标题直接传达“服务器状态，一眼看清”，实时连接只表达为“实时同步/自动刷新”，不展示实现技术。
- 全部已注册节点在线：绿色“全部服务器运行正常”。
- 存在离线/暂停/待安装节点：琥珀色“部分服务器需要关注”。
- 无节点：明确说明管理员添加节点并安装探针后才会展示数据，而不是显示“系统正常”。
- API 获取失败：保留上次数据，显示错误和重试按钮。

### 3.2 节点目录与 VPS 卡片

总览页是节点目录的唯一入口。目录保留状态、地区筛选和排序，并允许用户切换两种卡片密度；选择保存在当前浏览器中，刷新页面后继续沿用：

- 详细卡片：展示完整系统、资源用量、累计流量、实时网络、运行时间、探测质量和数据新鲜度，适合日常排障。
- 紧凑卡片：保留节点状态、位置、系统/架构、CPU、内存、磁盘、实时网络、运行时间、延迟和采集时间；通过降低卡片高度提升一屏可见数量。卡片在中等桌面保持两列、宽屏最多三列，长网速和运行时间完整换行，不以遮挡或截断内容换取密度。

详细卡片展示：

- 节点名称、配置城市/国家、完整 Linux 发行版、发行版家族/架构、Agent 版本。
- 待安装、在线、离线或暂停状态。
- CPU 百分比；内存、磁盘同时显示百分比和“已用 / 总量”，保留阈值色。
- 本次开机累计下载、上传、总流量，最近两次采样计算的上下行速度，以及精确到秒的运行时间。
- WebSocket 实时控制通道是否连接；该状态与心跳判定的节点健康状态分开显示。
- 1 分钟负载、24h 平均探测延迟和可用率。
- 延迟迷你趋势与“多久前采集”的新鲜度。

这些日常判断信息必须在首页直接可见，详情页只承载趋势和更深的主机信息。没有资源样本时不得展示 `0%`，应展示“尚未采集”以及安装或排障提示。

### 3.3 筛选与刷新

- 管理页保留名称搜索和状态筛选；地区信息自动识别，不把它作为新增节点前置条件。
- 默认通过同源 WebSocket 接收变化事件并重新读取 API；30 秒静默刷新作为降级保护。页面不可见时暂停，重新可见时立即刷新并重连。
- 手动刷新只禁用刷新按钮并保留现有内容，不切回整页骨架屏。

### 3.4 公共导航与状态文案

- 桌面顶部导航使用“总览、记录、公告”，移动端使用同一词汇与统一线性图标，不使用因平台而异的 Emoji。
- 页脚只说明产品定位，不把 Cloudflare Workers 等实现信息作为前台主信息。
- 首页无公告时明确显示“当前没有维护或故障公告，所有服务保持正常运行”。
- 404、接口错误、空记录与找不到节点必须分别说明原因和下一步，不能统一显示“暂无数据”。

## 4. 服务器详情

- 顶部：服务器名称、节点 ID、探针安装/在线状态、hostname、区域、位置和检查间隔。
- 资源区：CPU、内存、磁盘、负载卡片及 24h CPU/内存趋势。
- 网络与运行：相邻采样计算的实时上下行速率、本次开机累计流量、TCP 连接、进程数、运行时间和 24h 网速趋势；计数器重置不得产生负速率。
- 主机信息：发行版、架构、内核、CPU、核心数和虚拟化类型。
- 网络检查区：目标名称、正常/失败状态、延迟、HTTP 状态码、时间。
- 可用率：24h/7d/30d；无数据时显示 `--`，不等同于 0%。

## 5. 网络记录

前端把 24h/7d/30d/90d 转换为 API 的 `start_time`，而不是发送不存在的 `time_range` 参数。结果显示服务器名与目标名，失败数据的空延迟保持 `--`。桌面端使用表格，移动端改为记录卡片，避免页面级横向滚动。

## 6. 状态与无障碍

管理后台首次使用遵循渐进披露：基础监控只要求“添加节点 → 安装 Agent”；目标探测、告警和高级字段按需展开。目标创建只要求地址，告警规则优先选择推荐模板，通知渠道不得暴露 JSON 配置编辑器。

### 6.1 管理后台移动端

- 小于 `768px` 时隐藏桌面侧栏，通过顶部菜单按钮打开覆盖式导航抽屉；正文始终占用完整屏幕宽度。
- 通用数据表格在移动端改为“字段名 / 字段值”信息卡，操作按钮随卡片显示；桌面端继续使用可横向滚动的表格。
- 管理弹窗最大高度不得超过手机可视区域，超长表单在弹窗内部滚动；关闭按钮和确认操作始终可触达。
- Toast 使用左右安全边距，分页、筛选和操作栏允许换行，320px 宽度下不得出现页面级横向滚动。

每个数据组件必须覆盖：

- 初次加载骨架。
- 有数据的正常状态。
- 后台刷新状态。
- 空数据与待安装状态。
- Agent 离线或数据过期。
- API 错误和可操作的重试。

键盘焦点可见；状态不能只依赖颜色；错误容器使用 `role="alert"`；趋势 SVG 提供可读标签或作为装饰隐藏；正文对比度满足 WCAG AA。

## 7. 性能目标

| 指标 | 目标 |
|---|---|
| LCP | < 1.5s（正常边缘缓存） |
| CLS | < 0.1 |
| 初始交互 JS | < 200KB gzip |
| 实时与轮询 | WebSocket 指数退避重连；页面隐藏时不请求；保留 30 秒降级轮询 |
| 节点列表 | 单次最多 100 条，规模增长后启用分页/虚拟列表 |
