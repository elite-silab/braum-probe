# Braum 小白部署指南

> 目标：使用 GitHub 和 Cloudflare 网页部署一个完整的 Braum Worker。电脑端不需要运行 Wrangler 命令；只有安装 Agent 时需要在被监控 VPS 上执行后台生成的一条命令。

## 你最终会得到什么

一个 Worker 地址同时提供网站、后台、API 和 Agent 接口：

```text
https://braum-probe.你的Workers子域.workers.dev
```

生产配置分为两个 Cloudflare 位置，并在电脑上保留一份私密备忘录：

| 位置 | 内容 |
|---|---|
| GitHub 根目录 `wrangler.jsonc` | Worker 名称、D1/KV ID、Agent 地址 |
| Cloudflare Worker → Variables and Secrets | 初始邮箱、密码、JWT 与加密密钥 |
| 电脑上的根目录 `.env` | 上一行变量的本地备忘，不会自动上传或提交 Git |

不需要第二个 Worker、Pages、`PUBLIC_API_URL` 或 CORS 配置。`.dev.vars` 只在本地开发时使用，与生产 `.env` 分开。

## 第一步：Fork 项目

1. 打开项目 GitHub 页面。
2. 点击右上角 **Fork → Create fork**。
3. 后续修改配置时，直接在 GitHub 网页打开文件并点击铅笔按钮。

## 第二步：发布 Agent

1. 进入 Fork 后仓库的 **Actions**。
2. 首次使用时点击启用工作流。
3. 左侧选择 **Agent Release**。
4. 点击 **Run workflow**，等待任务变绿。
5. 打开 **Releases**，确认存在 Linux amd64、arm64 和对应 `.sha256` 文件。

Fork 仓库需要保持公开，否则 VPS 无法直接下载 Release。

## 第三步：创建 D1 和 KV

在 Cloudflare 控制台创建：

### D1

1. 打开 **Storage & Databases → D1**。
2. 创建名为 `braum-production` 的数据库。
3. 复制 **Database ID**。

### KV

1. 打开 **Storage & Databases → KV**。
2. 创建名为 `braum-cache` 的命名空间。
3. 复制 **Namespace ID**。

## 第四步：编辑一份配置

在 GitHub 网页打开根目录 `wrangler.jsonc`，修改以下内容：

```jsonc
"name": "braum-probe",

"AGENT_API_URL": "https://braum-probe.你的Workers子域.workers.dev",
"AGENT_RELEASE_BASE_URL": "https://github.com/elite-silab/braum-probe/releases/download/agent-v0.1.2",

"database_id": "刚复制的D1-ID",

"id": "刚复制的KV-ID"
```

Workers 子域可以在 Cloudflare 控制台的 Worker 页面查看。没有自定义域名也可以直接使用 `workers.dev` 地址。

`AGENT_RELEASE_BASE_URL` 默认指向官方已验证的 Agent 版本，通常不需要修改。只有自行编译并发布 Agent 时，才需要换成自己的下载地址。

配置里的 `REALTIME` Durable Object 会由 Cloudflare 在部署时自动创建。不要删除这一段，也不需要手工创建资源、填写 ID 或设置 WebSocket 地址。

修改后点击 **Commit changes**。普通配置可以提交，密码和密钥绝不能写入此文件。

## 第五步：创建唯一 Worker

1. 打开 Cloudflare **Workers & Pages**。
2. 选择 **Create application → Import an existing Git repository**。
3. 选择 Fork 后的仓库。
4. 填写：

| 设置 | 值 |
|---|---|
| Project name | `braum-probe` |
| Production branch | `main` |
| Root directory | 留空 |
| Build command | `pnpm --filter @braum/web build:worker` |
| Deploy command | `pnpm --filter @braum/web deploy:worker` |
| Node version | `22.14.0` 或更新的 22.x |

必须选择 Worker。如果页面要求填写 **Build output directory**，说明进入了 Pages 流程，请返回重新选择。

构建过程会自动生成 Next.js Worker、应用 D1 migrations 并部署，不需要单独运行数据库命令。

## 第六步：记录并填写生产变量

先在自己的电脑上复制 `.env.example`，将副本改名为 `.env`，填写自己的生产值。`.env` 只是帮助你防止遗漏的私密备忘录，不会自动上传到 Cloudflare。

然后对照 `.env`，进入 `braum-probe` Worker 的 **Settings → Variables and Secrets**，逐项添加：

| 名称 | 类型 | 内容 |
|---|---|---|
| `ADMIN_INITIAL_EMAIL` | Text | 自己设置的后台初始邮箱 |
| `ADMIN_INITIAL_PASSWORD` | Secret | 自己设置的后台初始密码 |
| `JWT_SECRET` | Secret | 随机 64 位字符串 |
| `JWT_REFRESH_SECRET` | Secret | 另一个不同的随机 64 位字符串 |
| `ENCRYPTION_KEY` | Secret | 再一个不同的随机 64 位字符串 |
| `TELEGRAM_BOT_TOKEN` | Secret | 可选；不用 Telegram 时无需添加 |

不要把 `.env` 上传到仓库，也不要照抄模板中的占位值。保存 Cloudflare 变量后点击重新部署。

## 第七步：检查并登录

打开以下页面：

| 页面 | 期望结果 |
|---|---|
| Worker 根地址 | Braum 状态首页 |
| `/health` | JSON 中显示 `status: ok` |
| `/admin` | 跳转到登录页 |

登录信息：

- 邮箱：Cloudflare 中的 `ADMIN_INITIAL_EMAIL`
- 密码：Cloudflare 中的 `ADMIN_INITIAL_PASSWORD`

## 第八步：安装第一台 VPS

1. 进入后台「VPS 节点」。
2. 点击添加节点，只填写节点名称即可。
3. 点击生成安装命令。
4. 把这一条命令粘贴到被监控 VPS 中执行。
5. 等待约一分钟。

节点 ID、系统、架构、位置、ISP 和资源数据会由 Agent 自动上报。需要监测网站或 DNS 时，到「监控目标」创建地址，再把目标分配给需要发起检查的节点；只创建目标但未分配节点不会产生探测结果。

## 本地体验（可选）

本地开发使用根目录 `.dev.vars`，不能使用保存生产值的 `.env`：

1. 安装 Node.js 22.14+ 和 pnpm。
2. 在文件管理器中复制 `.dev.vars.example`，将副本改名为 `.dev.vars`。
3. 直接编辑 `.dev.vars` 中的本地测试邮箱和密码，不要填写生产密钥。
4. 在仓库根目录运行：

```bash
pnpm install
pnpm dev
```

`pnpm dev` 会自动迁移本地 D1，网站、后台和 API 都位于 `http://localhost:3000`。

## 常见问题

### D1 ID 无效

检查根目录 `wrangler.jsonc` 中的 `database_id` 是否完整，并确认 D1 与 Worker 位于同一个 Cloudflare 账号。

### 首页可以打开，但登录失败

先打开 `/health`。如果健康检查正常，请确认 `ADMIN_INITIAL_EMAIL` 和五个 Secret 已添加到同一个 `braum-probe` Worker，并重新部署。

### 后台生成了错误的 Agent 地址

检查 `wrangler.jsonc` 中的 `AGENT_API_URL`，它应与浏览器正在访问的 Worker HTTPS 地址完全一致，末尾不要加 `/`。

### Agent 下载失败

确认 GitHub Release 已发布、仓库公开，并检查 `AGENT_RELEASE_BASE_URL` 是否指向自己的仓库。

### 旧的两个 Worker 怎么处理

确认新 `braum-probe` 的首页、登录、`/health` 和 Agent 上报均正常后，可以删除旧的 `braum-web` 与 `braum-worker`。不要在验证前删除，以便随时回退。

Agent 的升级、卸载和排障见 [Agent 使用指南](Agent使用指南.md)；开发者部署、备份和回滚见 [部署运维文档](部署运维文档.md)。
