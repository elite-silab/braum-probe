# Braum 版本发布指南

Braum 的网站与 Agent 位于同一个 GitHub 仓库，但使用独立版本号和标签，避免两种产物互相覆盖。

## 版本标签

| 发布对象 | 标签格式 | 示例 | GitHub Latest |
|---|---|---|---|
| 网站与 Worker | `web-v主版本.次版本.修订号` | `web-v0.1.0` | 是 |
| Agent | `agent-v主版本.次版本.修订号` | `agent-v0.1.1` | 否 |

历史标签 `v0.1.0` 是首个 Agent 版本，继续保留，不移动、不删除。从下一个 Agent 版本开始使用 `agent-v*` 格式。

## 网站发布

1. 确认 `main` 已通过 CI，并完成 Cloudflare 部署验证。
2. 更新根目录、`apps/web` 和 `apps/api` 中需要同步的网站版本号。
3. 在当前提交创建标签，例如 `web-v0.1.0`。
4. 推送标签后，`Web Release` 工作流会自动创建 GitHub Release、生成发行说明并标记为 Latest。

网站 Release 不上传 Agent 二进制文件。GitHub 自动提供当前版本的 Source code 压缩包。

## Agent 发布

1. 更新 Agent 代码、对应发行说明和 `AGENT_RELEASE_BASE_URL`，并通过 Go 测试。
2. 提交发行准备，但暂不推送 `main`。
3. 在该提交创建 `agent-v*` 标签并先推送标签；工作流会编译 amd64、arm64 文件和 SHA256 校验文件。
4. 验证 Release 与附件后，再推送 `main`，让默认安装地址开始使用新版本。

Agent 下载地址必须包含明确版本，不能使用仓库级 `/releases/latest/download`。GitHub 的 Latest 是整个仓库共用的，网站发版后会改变指向，可能导致 Agent 安装失败。

## 语义化版本

- 修订号：修复问题且保持兼容，例如 `0.1.0 → 0.1.1`。
- 次版本：增加兼容的新功能，例如 `0.1.0 → 0.2.0`。
- 主版本：包含不兼容变更，例如 `0.x → 1.0.0`。

已经推送的标签代表不可变版本。需要修复时发布新版本，不要强制移动旧标签。
