# Braum 环境变量与配置

> 版本：v3.1 · 更新：2026-08-17

## 配置原则

- 根目录 `.env` 是维护者电脑上的**生产变量私密备忘录**，不会自动上传到 Cloudflare。
- 根目录 `.dev.vars` 只保存 Wrangler **本地开发变量**，禁止填写生产密钥。
- 根目录 `wrangler.jsonc` 保存可以提交的非敏感配置和 Cloudflare 资源绑定。
- 生产变量仍需对照 `.env`，手动填写到 Cloudflare Worker 的 Variables and Secrets。
- 网站和 API 同源，不需要 `PUBLIC_API_URL`、`WORKER_API_URL` 或 CORS 白名单。
- 不在 `apps/web`、`apps/api` 等子目录创建重复环境文件。

## 生产 `.env`

在文件管理器中复制 `.env.example`，将副本改名为 `.env`，填写自己的生产值。真实 `.env` 已被 Git 忽略，只应保存在自己的电脑上。

| 变量 | Cloudflare 类型 | 必填 | 说明 |
|---|---|---|---|
| `ADMIN_INITIAL_EMAIL` | Text | 首次部署 | 初始 Owner 登录邮箱 |
| `ADMIN_INITIAL_PASSWORD` | Secret | 首次部署 | 初始 Owner 密码 |
| `JWT_SECRET` | Secret | 是 | Access Token 签名，使用随机长字符串 |
| `JWT_REFRESH_SECRET` | Secret | 是 | Refresh Token 签名，必须与 JWT_SECRET 不同 |
| `ENCRYPTION_KEY` | Secret | 是 | 告警渠道配置加密，必须使用第三个不同的值 |
| `TELEGRAM_BOT_TOKEN` | Secret | 按需 | Telegram 默认机器人 Token |

`.env` 是防止遗漏的备忘录，不是自动部署文件。填写完成后，进入 Cloudflare Dashboard → `braum-probe` → **Settings → Variables and Secrets**，逐项创建同名变量。未使用 Telegram 时可让 `TELEGRAM_BOT_TOKEN` 保持空白，并且无需在 Cloudflare 创建。

不要把 `.env`、真实邮箱、密码或 Token 提交到 Git、粘贴到聊天记录或放入截图。

## 开发 `.dev.vars`

本地开发时，在文件管理器中复制 `.dev.vars.example`，将副本改名为根目录 `.dev.vars`。Wrangler 会优先读取它，避免误用生产 `.env`。

| 变量 | 说明 |
|---|---|
| `ADMIN_INITIAL_EMAIL` | 本地首次登录邮箱，示例为 `admin@braum.local` |
| `ADMIN_INITIAL_PASSWORD` | 本地首次登录密码 |
| `JWT_SECRET` | 本地 Access Token 签名 |
| `JWT_REFRESH_SECRET` | 本地 Refresh Token 签名 |
| `ENCRYPTION_KEY` | 本地通知配置加密 |
| `TELEGRAM_BOT_TOKEN` | 可选的本地 Telegram Token |

`.dev.vars.example` 的值只用于开发，不能复制到 Cloudflare 生产环境。本地开发前务必创建 `.dev.vars`；如果它缺失，Wrangler 可能把 `.env` 当作本地变量来源。

## 生产普通配置

根目录 `wrangler.jsonc` 是唯一 Wrangler 配置：

| 配置 | 说明 |
|---|---|
| `name` | Worker 名称，默认 `braum-probe` |
| `APP_VERSION` | 健康检查显示的网站版本 |
| `AGENT_API_URL` | Agent 访问的 Worker HTTPS 地址 |
| `AGENT_RELEASE_BASE_URL` | Agent 二进制和校验文件目录 |
| D1 `database_id` | `DB` 绑定使用 |
| KV `id` | `CACHE` 绑定使用 |
| `triggers.crons` | 单一每分钟总调度器，在代码内按 UTC 时间分发心跳、告警、聚合和清理任务 |
| `REALTIME` Durable Object | WebSocket 连接中心，由部署自动创建，无需填写 ID |

`AGENT_API_URL` 必须能从 VPS 访问，生产环境使用 HTTPS，末尾不要添加 `/`。D1 和 KV ID 是资源绑定，不属于 Worker Variables and Secrets，因此继续保存在 `wrangler.jsonc`。

## Cloudflare Bindings

| Binding | 类型 | 作用 |
|---|---|---|
| `DB` | D1 | 节点、指标、探测、告警和审计 |
| `CACHE` | KV | 登录接口的低频分布式限流；额度异常时自动降级，不影响 Agent 上报 |
| `ASSETS` | Workers Assets | Next.js 静态资源 |
| `REALTIME` | Durable Object | Agent 与状态页的休眠 WebSocket 连接 |

四个绑定属于同一个 Worker。`REALTIME` 的 class 和 migration 已在 `wrangler.jsonc` 中声明；普通用户不要删除，也不需要在 Cloudflare 控制台手工创建资源。

## Agent 配置

VPS 安装后的配置位于 `/etc/braum-agent/config.json`，权限为 `0600`：

```json
{
  "server": "https://braum-probe.example.workers.dev",
  "node_id": "节点ID",
  "agent_secret": "仅本机保存，数据库无明文",
  "interval": 60
}
```

首次注册成功后，Agent 会删除一次性令牌并写入节点独立密钥。不要把一个节点的配置复制到另一台 VPS。

Agent 会从 `server` 自动把 `https://` 转换为 `wss://` 并连接 `/api/agent/v1/ws`。配置文件不增加 WebSocket URL、端口、证书或重连参数。

## 检查清单

- 真实 `.env` 和 `.dev.vars` 均只存在于本机且被 Git 忽略；
- `.env` 只包含六个需要手动填写到 Cloudflare 的生产变量；
- `.dev.vars` 只包含开发值，不使用任何生产密钥；
- Cloudflare 中 `ADMIN_INITIAL_EMAIL` 选择 Text，其余五项选择 Secret；
- 根目录只有一份 `wrangler.jsonc`，子目录没有重复环境文件；
- D1 与 KV ID 属于当前 Cloudflare 账号；
- `AGENT_API_URL` 与实际 Worker 地址一致；
- `JWT_SECRET`、`JWT_REFRESH_SECRET` 和 `ENCRYPTION_KEY` 互不相同；
- GitHub Agent Release 可以公开下载。

完整网页操作见 [小白部署指南](小白部署指南.md)。
