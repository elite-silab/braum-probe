# Braum 环境变量与配置

> 版本：v2.1 · 更新：2026-07-25

## 配置原则

- 本地开发只有一个入口：仓库根目录 `.env`。
- `.dev.vars` 已停止使用，不需要创建，也没有对应模板。
- 生产普通配置放在 `apps/api/wrangler.toml`。
- 生产密钥只放在 Cloudflare 的 Variables and Secrets 页面，不写入 Git。
- Web 的生产 API 地址放在 Cloudflare Pages 的 `PUBLIC_API_URL`。

这样既去掉本地重复配置，也避免为了“一个文件”而把生产密码提交到仓库。

## 本地 `.env`

在文件管理器中复制 `.env.example`，将副本改名为 `.env`。macOS/Windows 用户也可以双击仓库根目录的本地启动文件，它会自动创建并打开 `.env`。

API 的 `wrangler dev` 和 Astro Web 会同时读取这个根目录文件。不要再创建 `apps/api/.dev.vars`、根目录 `.dev.vars` 或 `apps/web/.env`。

| 变量 | 新手是否要改 | 说明 |
|---|---|---|
| `ADMIN_INITIAL_PASSWORD` | 建议 | 本地后台首次登录密码 |
| `PUBLIC_API_URL` | 通常不用 | Web 访问本地 Worker 的地址 |
| `JWT_SECRET` | 通常不用 | 仅本地 Access Token 签名 |
| `JWT_REFRESH_SECRET` | 通常不用 | 仅本地 Refresh Token 签名 |
| `ENCRYPTION_KEY` | 通常不用 | 仅本地通知配置加密 |
| `CORS_ORIGINS` | 通常不用 | 允许访问本地 API 的 Web Origin |
| `AGENT_API_URL` | 调试 Agent 时 | 后台生成 Agent 安装命令使用的 API 地址 |
| `AGENT_RELEASE_BASE_URL` | 调试安装时 | Agent 二进制和校验文件目录 |
| `TELEGRAM_BOT_TOKEN` | 可选 | Telegram 默认机器人 Token |

`.env.example` 里的密钥明确标记为本地示例值，不能复制到生产环境。

## 生产普通配置

直接编辑 `apps/api/wrangler.toml` 的正式环境：

| 变量 | 示例 | 说明 |
|---|---|---|
| `APP_VERSION` | `0.1.0` | 健康检查与 API 版本 |
| `CORS_ORIGINS` | `https://status.example.com` | Web Origin 白名单，多个值用英文逗号分隔 |
| `AGENT_API_URL` | `https://api.example.com` | 后台生成安装命令时使用的公开 Worker 地址 |
| `AGENT_RELEASE_BASE_URL` | `https://github.com/elite-silab/braum-probe/releases/latest/download` | Agent 二进制与 `.sha256` 文件目录 |
| D1 `database_id` | Cloudflare 提供的 UUID | `DB` 绑定使用 |
| KV `id` | Cloudflare 提供的 ID | `CACHE` 绑定使用 |

`AGENT_API_URL` 必须能从 VPS 访问，正式环境只能使用 HTTPS，末尾不要添加 `/`。

## 生产密钥

进入 Cloudflare Dashboard → Worker → Settings → Variables and Secrets。以下值选择 Secret/加密类型：

| Secret | 必填 | 说明 |
|---|---|---|
| `JWT_SECRET` | 是 | 随机至少 32 字节，建议使用密码管理器生成 64 位字符串 |
| `JWT_REFRESH_SECRET` | 是 | 使用另一个不同的随机字符串 |
| `ENCRYPTION_KEY` | 是 | 通知渠道 AES-GCM 加密密钥 |
| `ADMIN_INITIAL_PASSWORD` | 首次部署 | 初始 Owner 密码 |
| `TELEGRAM_BOT_TOKEN` | 按需 | Telegram 默认配置 |

不要把这些值写入 `.env.example`、`wrangler.toml`、截图、聊天记录或 Git 历史。

## Web 生产变量

进入 Cloudflare Pages → Settings → Variables and Secrets，添加：

| 变量 | 说明 |
|---|---|
| `PUBLIC_API_URL` | 浏览器与 Astro SSR 请求的正式 Worker HTTPS 地址 |

修改后需要重新部署 Pages。Workers 的 `CORS_ORIGINS` 也必须包含这个 Pages 域名。

## Cloudflare bindings

| Binding | 类型 | 作用 |
|---|---|---|
| `DB` | D1 | 配置、指标、探测、告警、审计 |
| `CACHE` | KV | 最新探测结果和限流状态 |

Web 只通过 `PUBLIC_API_URL` 调用 Worker，不绑定 D1/KV，也不再运行另一套 Pages Functions 管理 API。

## Agent 安装后的配置

VPS 安装后配置位于 `/etc/braum-agent/config.json`，权限为 `0600`，所有者为 `braum-agent`：

```json
{
  "server": "https://api.example.com",
  "node_id": "tokyo-01",
  "agent_secret": "仅本机保存，数据库无明文",
  "interval": 60
}
```

首次安装时短暂存在 `enrollment_token`；注册成功后 Agent 会原子重写配置，删除一次性令牌并写入长期密钥。不要手动复制长期密钥到其他节点。

## 新手检查清单

- 仓库里只有 `.env.example`，没有真实 `.env`；
- 没有创建 `.dev.vars`；
- `wrangler.toml` 正式环境不再包含 `replace-with`；
- 三个生产安全密钥互不相同；
- Pages 的 `PUBLIC_API_URL` 是 HTTPS Worker 地址；
- Worker 的 `CORS_ORIGINS` 包含 Pages 地址；
- Agent Release URL 能在浏览器打开。

完整网页操作见 [小白部署指南](小白部署指南.md)，命令行检查见 [部署运维文档](部署运维文档.md)。
