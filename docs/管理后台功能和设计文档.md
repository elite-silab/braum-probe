# Braum 管理后台功能与设计

> 版本：v2.1 · 更新：2026-07-27

## 1. 后台职责

管理后台是 Workers 控制面的操作界面，负责 VPS Agent 生命周期、探测目标、资源/网络告警、事件公告、系统配置和审计。前端不直接访问 D1/KV，所有操作统一调用 Workers `/api/admin/v1/*`。

## 2. 角色权限

| 角色 | 权限 |
|---|---|
| Owner | 全部权限；用户、系统设置、删除节点等高风险操作 |
| Admin | 节点/Agent、目标、告警、通知和事件管理 |
| Viewer | 已认证只读 |

Workers 每次管理请求都会从 D1 读取用户当前角色和状态，不只信任 JWT 内旧角色。建议再用 Cloudflare Access 保护 `/admin`。

## 3. 控制台

控制台使用客户端 JWT 请求同源管理 API，避免服务端组件无法读取浏览器 Token 导致统计恒为零。

内容包括：

- 在线 VPS、待安装 Agent、监控目标和活跃事件。
- 核心两步清单：添加 VPS → 安装 Agent；网络探测与告警明确标记为可选增强。
- 根据当前状态给出唯一的“下一步”按钮，避免把所有模块同时压给首次用户。
- 最近节点、Agent 版本和最后心跳。
- 加载骨架、API 错误与重试。

## 4. VPS 节点与 Agent

### 4.1 新增节点

新增流程坚持轻量原则：节点名称是唯一必填项。节点 ID 由 Workers 生成，地区、国家、城市、坐标和 ISP 在 Agent 首次注册时利用 Cloudflare 请求信息自动识别，采集间隔默认 60 秒；关联目标与采集频率放在折叠的“可选设置”中。

编辑节点时显示名称、关联目标、采集频率和启用/暂停状态。自动位置不准确时，管理员可以展开“手动修正位置”；系统生成的节点 ID 只读，不要求用户理解或维护。

创建节点后自动进入 Agent 安装步骤：

1. Workers 生成 15 分钟有效的一次性注册令牌。
2. 后台展示完整安装命令、过期时间和复制按钮。
3. 管理员在目标 VPS 使用 sudo/root 执行。
4. Agent 换取长期节点密钥并删除一次性令牌。
5. 注册时自动保存系统信息与位置，首次心跳后节点从“待安装”变为“在线”。

安装命令属于敏感短期凭据，不应发到群聊、工单正文或写入仓库。

### 4.2 重装与吊销

- “重装”只生成新的注册令牌，旧 Agent 在新 Agent 完成注册前仍可工作。
- 新注册完成后长期密钥自动轮换，旧 Agent 立即失效。
- 管理端可显式吊销凭据；吊销后清空心跳并将节点置为离线。
- 删除节点会级联删除 Agent 凭据、主机信息和资源指标。

### 4.3 节点状态

| 状态 | 含义 |
|---|---|
| 待安装 | 没有 Agent 凭据 |
| 在线 | 已注册且心跳未超时 |
| 离线 | 心跳超过 `max(3 × interval, 180s)` |
| 暂停 | 管理员暂停，下发空任务列表 |

### 4.4 资源、网络与运行时间

Agent 每次心跳上报 CPU、内存、磁盘、负载、累计网络收发字节、TCP 连接、进程数和系统运行秒数。首页节点卡片展示本次开机累计下载/上传流量与运行时间；节点详情根据相邻采样差计算上下行速率并绘制 24 小时趋势。该计算复用现有指标，不增加额外 Agent 配置或 D1 写入。

Linux 网络累计计数器会在系统重启后归零，因此界面明确使用“本次开机累计”口径。发生计数器回退时，该采样区间速率按零处理，不能显示负数或异常尖峰。

## 5. 监控目标

- 网络探测不属于服务器资源监控的必经步骤，后台必须明确标记为可选。
- 新增时地址是唯一必填项：带 `http://` 或 `https://` 自动识别为 HTTP，否则识别为 DNS；显示名称从域名自动生成。
- 期望状态码、超时和自定义名称放入折叠的“可选设置”。保存 HTTP 前阻止私网/回环和危险重定向目标。
- 目标通过节点编辑页关联；Agent 心跳只得到分配给自己的启用目标。
- Agent 单次结果上报最多 100 条，服务端再次校验目标确实属于该节点。

## 6. 告警

指标包括：

- VPS 资源：CPU、内存、磁盘、1 分钟负载。
- Agent 状态：心跳中断秒数。
- 网络探测：可用率、延迟、连续失败。

新增规则优先展示 Agent 离线、CPU、内存、磁盘和网络可用率推荐模板，指标、运算符和观察窗口收进高级设置。资源指标按持续时间窗口平均值判断，避免单次抖动误报。

通知渠道只展示当前真实支持的 Telegram 和 Webhook，并使用 Chat ID、Bot Token、Webhook URL 普通字段，禁止要求用户手写 JSON。启用渠道自动关联全部已启用规则，新规则也自动使用全部已启用渠道。渠道配置加密保存；编辑时回填 Chat ID 和“Token 已配置”状态，但不返回密钥明文。已保存渠道支持直接发送测试消息。

## 7. 事件、设置与审计

- 事件公告支持调查中、已定位、监控中、已解决、计划维护及时间线更新。
- Owner 管理站点名称、时区、保留策略和用户。
- 审计记录操作人、对象、IP 和变更；密码、Token、Secret、Authorization 等递归脱敏。

## 8. 远程终端

远程终端属于 P1，不在当前管理后台显示伪按钮。实施前必须具备：二次确认、短时会话票据、Agent 主动 WebSocket、中继隔离、会话吊销、权限检查和完整审计。永久心跳密钥不得直接暴露给浏览器。
