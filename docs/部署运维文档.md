# Braum 部署与运维

> 版本：v2.1 · 更新：2026-07-25

## 1. 部署拓扑

- Workers：唯一 API、Agent 注册、指标接收、配置、告警和 Cron。
- D1：持久数据；KV：缓存与限流。
- Pages：公共页面和管理后台，统一调用 Workers。
- VPS Agent：主动 HTTPS 连接 Workers，不开放入站 Agent 端口。

## 2. 首次部署

首次部署默认采用 GUI 流程：在 GitHub Fork 后，通过 Cloudflare Dashboard 创建 D1/KV、连接 Git 仓库并填写 Secrets。用户只需编辑 `apps/api/wrangler.toml` 的普通配置，不必在终端逐条执行 Wrangler 命令。

完整的逐屏操作见 [小白部署指南](小白部署指南.md)。核心顺序是：

1. GitHub Actions 网页发布 Agent；
2. Cloudflare 网页创建 D1 和 KV；
3. GitHub 网页编辑 `wrangler.toml` 中的资源 ID；
4. Workers Builds 连接仓库，部署命令选择 `pnpm --filter @braum/api deploy:full`；
5. Worker 设置页填写四个生产 Secrets；
6. Pages 连接同一仓库并填写 `PUBLIC_API_URL`；
7. 回填正式的 `CORS_ORIGINS` 和 `AGENT_API_URL`。

`deploy:full` 会在 Cloudflare CI 中自动应用待执行的 D1 migrations，再部署 Worker。若 Agent Release URL 仍是占位符，安装脚本接口会返回 503，这是预期的安全失败。

## 3. Agent Release 与安装

推送 `v*` 标签触发 `agent-release.yml`，生成：

```text
braum-agent_linux_amd64
braum-agent_linux_amd64.sha256
braum-agent_linux_arm64
braum-agent_linux_arm64.sha256
```

在后台添加 VPS 后复制安装命令。脚本校验 HTTPS、TLS 1.2 和 SHA-256，随后以 `braum-agent` 低权限用户安装 systemd 服务。

```bash
systemctl status braum-agent
journalctl -u braum-agent -f
/usr/local/bin/braum-agent --version
```

## 4. Agent 升级、重装与卸载

当前 P0 使用后台“重装”生成新注册命令。新 Agent 注册成功会轮换密钥，旧 Agent 失效。

手动停止/卸载：

```bash
sudo systemctl disable --now braum-agent
sudo rm -f /etc/systemd/system/braum-agent.service
sudo systemctl daemon-reload
sudo rm -f /usr/local/bin/braum-agent
sudo rm -rf /etc/braum-agent
sudo userdel braum-agent
```

卸载 VPS 文件不会自动删除控制面节点；应在后台吊销或删除节点。

## 5. Cron

| 表达式 | 任务 |
|---|---|
| `* * * * *` | 检查 Agent 心跳并标离线，不执行 VPS 探测 |
| `*/2 * * * *` | 评估资源、心跳与探测告警 |
| `0 * * * *` | 上一完整小时聚合 |
| `0 2 * * *` | 上一完整日聚合 |
| `0 3 * * *` | 清理过期指标、探测、聚合、审计和令牌 |

HTTP/DNS 探测由 VPS Agent 执行。Workers Cron 不代表任何 VPS 地理位置，也不能更新节点心跳。

## 6. 备份与恢复

变更迁移或大版本升级前导出 D1：

```bash
pnpm --dir apps/api exec wrangler d1 export braum-production --remote --output ../../braum-backup.sql --config wrangler.toml
```

备份文件包含用户、通知配置密文和 Agent 密钥摘要，应按敏感数据保存。恢复后已安装 Agent 可继续使用相同摘要；若凭据表未恢复，需要为节点重新生成安装命令。

## 7. 监控与容量

重点观察：

- Worker 5xx、CPU 时间和请求量。
- D1 写入/读取、存储与锁冲突。
- 心跳 401/400、注册失败和指标校验失败。
- 待安装节点、离线节点、Agent 版本分布。
- 通知发送失败和 Cron 错误日志。

资源指标写入/天约为 `节点数 × 86400 / interval`。例如 100 节点、60 秒间隔即 144,000 条/天，通常已不适合免费 D1 配额。应提高间隔、缩短原始保留或规划专用时序数据层。

## 8. 常见故障

### 后台无法生成可用安装脚本

- 检查 `AGENT_API_URL` 是否为公开 HTTPS 地址。
- 检查 `AGENT_RELEASE_BASE_URL` 是否真实存在且没有 `replace-with`。
- 检查 GitHub Release 是否同时包含二进制和 `.sha256`。

### Agent 注册返回 401

- 注册令牌可能超过 15 分钟、已经用过或属于其他节点。
- 在后台重新生成命令；不要复用旧命令。

### Agent 心跳返回 401

- 凭据已被重装轮换、后台吊销或节点已删除。
- 重新生成安装命令并安装。

### 节点在线但没有探测结果

- 编辑节点，确认已关联启用目标。
- 查看 Agent 日志中的 DNS/HTTP 错误。
- 多个长超时任务不会阻塞心跳，但同一时间只运行一批探测；适当降低目标超时。

### 页面显示旧资源数据

- 页面会保留最后样本并显示采集时间。
- 检查 Agent systemd 状态、VPS 到 Workers 的网络和本地时钟。

## 9. 安全运维

- 用 Cloudflare Access 保护 `/admin`。
- 定期轮换 JWT/加密密钥时制定会话和密文迁移窗口。
- 发现安装命令泄漏时立即重新生成；发现长期密钥泄漏时吊销凭据。
- 不在 Worker 日志、工单和聊天中粘贴安装命令或 Agent 配置。
- 远程终端 P1 上线前必须完成独立威胁建模和会话审计验证。

## 10. 高级：命令行首次部署

以下方式只供熟悉终端的开发者使用。普通用户应优先按照 [小白部署指南](小白部署指南.md) 在网页中完成部署。

```bash
pnpm install
pnpm --dir apps/api exec wrangler d1 create braum-production --config wrangler.toml
pnpm --dir apps/api exec wrangler kv namespace create CACHE --config wrangler.toml
```

把资源 ID 和正式网址写入 `apps/api/wrangler.toml`，再设置生产 Secrets：

```bash
pnpm --dir apps/api exec wrangler secret put JWT_SECRET --config wrangler.toml
pnpm --dir apps/api exec wrangler secret put JWT_REFRESH_SECRET --config wrangler.toml
pnpm --dir apps/api exec wrangler secret put ENCRYPTION_KEY --config wrangler.toml
pnpm --dir apps/api exec wrangler secret put ADMIN_INITIAL_PASSWORD --config wrangler.toml
```

应用迁移并部署：

```bash
pnpm --filter @braum/shared build
pnpm --filter @braum/api deploy:full
PUBLIC_API_URL=https://api.example.com pnpm --filter @braum/web build
pnpm --dir apps/api exec wrangler pages deploy ../web/dist --project-name braum-web
```
