# Braum 部署与运维

> 版本：v3.0 · 更新：2026-07-27

## 1. 部署拓扑

- `braum-probe`：唯一 Cloudflare Worker，运行 Next.js、Hono API、Agent 接口和 Cron。
- D1：持久数据；KV：缓存与限流；Workers Assets：Next.js 静态资源。
- VPS Agent：主动通过 HTTPS 连接同一个 Worker，不开放入站 Agent 端口。

唯一生产配置是根目录 `wrangler.jsonc`。

## 2. Cloudflare Git 部署

普通用户应按照 [小白部署指南](小白部署指南.md) 使用网页完成。Cloudflare Git 集成填写：

| 设置 | 值 |
|---|---|
| Project name | `braum-probe` |
| Root directory | 仓库根目录 |
| Build command | `pnpm --filter @braum/web build:worker` |
| Deploy command | `pnpm --filter @braum/web deploy:worker` |
| Node.js | 22.12.0+ |

构建命令将 Next.js 转换为 OpenNext Worker；部署命令先应用远程 D1 migrations，再部署唯一 Worker。

生产 Secrets 只放在 Worker 的 Variables and Secrets：`JWT_SECRET`、`JWT_REFRESH_SECRET`、`ENCRYPTION_KEY`、`ADMIN_INITIAL_PASSWORD`，以及可选的 `TELEGRAM_BOT_TOKEN`。

## 3. Agent Release 与安装

面向普通用户的完整安装、升级、卸载和排障流程见 [Agent 使用指南](Agent使用指南.md)。本节只保留发布与运维速查。

Agent Release 工作流生成：

```text
braum-agent_linux_amd64
braum-agent_linux_amd64.sha256
braum-agent_linux_arm64
braum-agent_linux_arm64.sha256
```

后台生成的安装脚本会校验 HTTPS、TLS 与 SHA-256，以低权限 `braum-agent` 用户安装 systemd 服务，并在升级或重装时显式重启服务。

```bash
systemctl status braum-agent
journalctl -u braum-agent -f
/usr/local/bin/braum-agent --version
```

## 4. Agent 重装与卸载

后台重新生成安装命令会轮换节点密钥，旧 Agent 凭据立即失效。

```bash
sudo systemctl disable --now braum-agent
sudo rm -f /etc/systemd/system/braum-agent.service
sudo systemctl daemon-reload
sudo rm -f /usr/local/bin/braum-agent
sudo rm -rf /etc/braum-agent
sudo userdel braum-agent
```

卸载 VPS 文件不会删除后台节点，需要在管理后台另行吊销或删除。

## 5. Cron

| 表达式 | 任务 |
|---|---|
| `* * * * *` | 检查 Agent 心跳并标记离线 |
| `*/2 * * * *` | 评估资源、心跳和探测告警 |
| `0 * * * *` | 小时聚合 |
| `0 2 * * *` | 日聚合 |
| `0 3 * * *` | 清理过期指标、探测、聚合、审计和令牌 |

HTTP/DNS 探测由 VPS Agent 执行。Workers Cron 不代表 VPS 地理位置。

## 6. 命令行部署（开发者）

```bash
pnpm install
pnpm --filter @braum/web build:worker
pnpm --filter @braum/web deploy:worker
```

也可以使用根命令完成构建和部署：

```bash
pnpm deploy
```

设置生产 Secret：

```bash
pnpm exec wrangler secret put JWT_SECRET --config wrangler.jsonc
pnpm exec wrangler secret put JWT_REFRESH_SECRET --config wrangler.jsonc
pnpm exec wrangler secret put ENCRYPTION_KEY --config wrangler.jsonc
pnpm exec wrangler secret put ADMIN_INITIAL_PASSWORD --config wrangler.jsonc
```

## 7. D1 备份与恢复

重大升级前导出 D1：

```bash
pnpm exec wrangler d1 export DB --remote --config wrangler.jsonc --output braum-backup.sql
```

备份包含用户、通知配置密文和 Agent 密钥摘要，应按敏感数据保存。恢复后如果 Agent 凭据表缺失，需要为节点重新生成安装命令。

## 8. 回滚

应用回滚使用 Cloudflare Worker 的版本历史或 Wrangler：

```bash
pnpm exec wrangler versions list --config wrangler.jsonc
pnpm exec wrangler versions rollback --config wrangler.jsonc
```

D1 优先使用 Cloudflare Time Travel。不要通过修改已有 migration 或执行高风险 down migration 回滚。

## 9. 监控与容量

重点观察 Worker 5xx、CPU 时间、D1 读写、心跳 401、Agent 注册失败、通知失败与 Cron 错误。

资源指标写入量约为 `节点数 × 86400 / 上报间隔`。例如 100 个节点、60 秒间隔约为 144,000 条/天；达到此规模时应提高间隔、缩短原始数据保留或规划时序数据层。

## 10. 常见故障

### 首页正常但登录失败

检查同一 Worker 的 `/health`，再确认四个生产 Secrets 已保存并重新部署。前端使用同源 API，不需要单独配置 API 地址。

### 无法生成安装脚本

检查 `wrangler.jsonc` 中的 `AGENT_API_URL` 和 `AGENT_RELEASE_BASE_URL`，确认 Release 同时包含二进制与 `.sha256`。

### Agent 注册或心跳返回 401

注册令牌可能过期、已使用，或长期凭据已轮换。请在后台重新生成安装命令，不要复用旧命令。

### 节点在线但没有探测结果

确认节点已关联启用的目标，并查看 Agent 日志中的 DNS/HTTP 错误。

## 11. 安全运维

- 使用 Cloudflare Access 额外保护 `/admin`。
- 不在日志、工单或聊天中粘贴安装命令与 Agent 配置。
- 安装命令泄漏时重新生成；长期密钥泄漏时立即吊销。
- 远程终端上线前必须完成独立威胁建模、短期会话票据和完整审计。
